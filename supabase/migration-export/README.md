# Переход на независимую базу

Сайт больше не использует остановленную базу Lovable: каталог, вход, заказы, избранное, подписка, настройки и статистика обращаются к вашему внешнему проекту.

## SQL Editor — выполнить по порядку

1. `01_schema.sql` — таблицы, права, политики и функции. Теперь можно запускать повторно: существующие данные не удаляются.
2. `02_data.sql` — 641 видимая работа и 9 спецпроектов. Существующие записи остаются без изменений; 15 скрытых дублей не включены.
3. `03_current_updates.sql` — время смены статусов заказов, индексы, безопасные права RPC, первоначальный администратор и перенос «Свода времени», «Купола времени» и индивидуального проекта №05 в «Роспись / Потолки».
4. `04_verify.sql` — проверка количества картин, привязок, функций и роли администратора.

Если 01 и 02 уже выполнены, выполните 01 повторно, затем 03 и 04; 02 можно повторить для восстановления недостающих записей.

## Вход

В настройках Authentication внешнего проекта задайте:
- Site URL: `https://prosetskaya.ru`
- Redirect URLs: `https://prosetskaya.ru/**` и используемый адрес предпросмотра Lovable с `/**`, если нужен вход в предпросмотре.
- Email/password включён, подтверждение email включено.
- SMTP для приглашений и восстановления пароля: проверьте доставку письма до открытия сайта посетителям.

Аккаунты старой базы не переносятся этими SQL: зарегистрируйтесь заново. Первый аккаунт получает роль администратора. Если аккаунт уже был зарегистрирован, 03 назначит первым администратором самый ранний аккаунт, только когда ни одного администратора ещё нет.

## Timeweb

- Закрытая переменная `EXTERNAL_SUPABASE_SECRET_KEY`: новый секретный ключ вашего внешнего проекта. Не добавлять в Git, SQL, VITE-переменные или переписку. Ранее отправленный в чат ключ нужно перевыпустить.
- Для входа и заказов по договору закрытый ключ не нужен; он нужен приглашениям пользователей и онлайн-платежам ЮKassa.
- Для браузера в России `VITE_EXTERNAL_SUPABASE_URL=https://api.prosetskaya.ru`. Прокси уже направлен на внешний проект. Сервер использует прямой адрес проекта.
- После установки переменной запустите `node scripts/setup-storage.mjs` один раз на хостинге: создаётся приватное хранилище `artworks`. Политики доступа создаёт 01.
- Укажите данные ЮKassa в админке и адрес webhook `https://prosetskaya.ru/api/public/yookassa` у платёжного провайдера.

## Фото

В Git хранятся список фото и загрузчик, а не тяжёлые картинки. Docker скачивает их перед сборкой и включает в образ сайта. Уже собранный сайт не обращается к Lovable за этими фото. При новой сборке источник фото должен оставаться доступным; новые загрузки администратора хранятся в вашем внешнем хранилище.

Скрипты не переносят старые аккаунты, заказы, посещения или файлы закрытого хранилища. Остановленная старая база недоступна для свежей сверки; данные 02 — сохранённый экспорт.
